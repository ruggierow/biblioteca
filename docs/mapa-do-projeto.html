As três regras que evitam voltar ao caos

REGRA 1
Uma cópia só do motor web
Edite motor-web/biblioteca.html e mais nada. O app macOS chega nele por link simbólico; os atalhos procuram ./biblioteca.html e caem para ../biblioteca.html. Achou outra cópia? É lixo — apague, não sincronize.
REGRA 2
Uma versão só
O arquivo VERSION na raiz carimba os cinco pontos de uma vez.
echo "1.8.1" > VERSION && ./bin/versionar.sh
REGRA 3
Mexeu no contrato, confira nos cinco
O que está em comum/ tem implementações paralelas em Swift, Dart e JavaScript. Uma alteração ali é uma alteração em todas — os apps trocam dados entre si.

Os dois tratavam o scanner, de formas diferentes; nenhum tratava a câmera da capa. Agora os quatro seguem o mesmo comportamento: mesmos quatro estados, mesmo texto, mesmos botões. Dois ganhos que faltavam em ambos — restrita deixou de ser confundida com negada (não adianta oferecer Configurações a quem não pode mudar), e ao voltar das Configurações o app reconsulta e abre a câmera sozinho. A galeria fica de fora de propósito: no Android 13+ o seletor do sistema dispensa permissão, e pedi-la produziria uma recusa falsa.

O link simbólico era o único risco real da estrutura: se o Xcode empacotasse o link em vez do arquivo, o app abriria vazio. Empacota o conteúdo.

O que ficou em aberto

O release Android assina com a chave de debug
O android/app/build.gradle.kts ainda tem o TODO padrão do Flutter. Antes de publicar em qualquer lugar, configure uma chave de verdade.
Um erro pré-existente no flutter analyze
test/widget_test.dart referencia uma classe MyApp que nunca existiu — sobra do template. É o único erro do projeto, e conserto de um minuto.
A árvore ainda não está toda sob git
motor-movel/android tem remoto no GitHub; motor-movel/ios tem repositório local com um único commit e muito trabalho não commitado. O resto — inclusive o motor web — não está versionado.
